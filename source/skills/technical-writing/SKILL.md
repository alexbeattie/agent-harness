# Technical writing

Choose the document mode before drafting: tutorial for a guided first success, how-to for a task, reference for exact behavior, explanation for a mental model. Name audience and prerequisite knowledge. Lead with the result, then put constraints next to the action they affect. Use one concept per sentence where ambiguity would be costly. Prefer concrete verbs and stable names. Give examples that can be run or verified; never imply testing that did not happen. Vary rhythm, cut duplicated headings, and leave open questions visible. For repository work, follow its style and delivery rules.
